# Herdr Android · UX-D0 / 工作台（Board）设计规格 v0.1

> 阶段：**设计评审稿，不授权 Pi 编码**  
> 视觉方向：Graphite × Editorial  
> 依据：`HERDR-ANDROID-UI-ENGINEERING-CONTRACT-v0.1.md`、`STATUS-BRIEF-FOR-EXTERNAL-REVIEW.md`。  
> 事实边界：当前项目有多主机连接，但**尚无跨主机聚合**；`blocked` 不等价于已有结构化审批请求；没有可靠的活动摘要、事件历史或等待时长时不得推断生成。

## 0. 要解决的用户问题与成功标准

**用户任务**：手机单手打开后，在 3 秒内辨认“是否有人等我、哪个任务、属于哪个主机”，然后一击进入正确对话。

**成功条件（设计目标，不是已通过测试）**：
1. 默认只突出需要用户关注的条目；其他条目可快速扫描。
2. 无待处理时不出现空的大卡片，极少 Agent 的页面仍有良好节奏。
3. 连接状态、数据是否实时、Agent 自身状态不混淆。
4. 可以从屏幕阅读器、窄屏及放大字号中正确操作。
5. UI 设计不依赖尚未实现的跨主机聚合、自动摘要或审批能力。

## 1. 范围与暂定决策

- **本版布局选择**：Attention First（重要条目容器 + 普通条目紧凑列表）。
- **本版数据范围**：单个所选主机。主机切换器显示具体主机；不得默认显示「全部主机」或跨主机总数，直到聚合层正式完成并通过测试。
- **本版主要行为**：进入对话；明确同步/重连；主机切换；技术诊断入口。Blocked 不提供读屏一键批准。
- **导航**：现阶段仅「工作台」「主机」两个底部主入口；没有持久事件来源前不增加「活动」空壳入口。
- **需要用户确认**：是否将主机选择器从顶栏下拉改为标题下方小按钮；已完成分区默认收起还是默认展示最近一条。

## 2. 页面结构（从上到下）

### 2.1 顶部区域
- 第一行：`工作台 / Agents` 大标题；右侧设置入口（可保留已有显式刷新入口，不因概念稿移除已有能力）。
- 第二行：主机选择器（名称、必要时显示状态）；单主机也要能辨认目标。
- 连接正常时用低强调、简短的已连接状态；**不使用永久成功横幅**。
- 连接中/恢复中/离线、数据过期时由独立状态条呈现；连接成功但数据仍旧时必须标记旧数据。
- 有 Pending/Unknown 写操作时，页面顶部出现持久可发现入口，优先级不低于 Blocked 分组。

### 2.2 内容区
排序采用以下逻辑：
1. 写操作结果未知的提示入口（如存在）。
2. `blocked`：有 1–2 条则轻强调容器；更多则突出前 2 条 + 紧凑列表或“查看全部”。不可暗示都能安全一键批准。
3. `working`：紧凑行。
4. `done`：低强调，可折叠；如果有完成但未查看的可靠状态，可明确区别于已查看，否则不推断。
5. `idle` 与 `unknown`：低强调独立组，不能混作同一个语义。

每个条目的强弱顺序：**任务标题 → 状态/可见真实原因 → Agent + 项目 + 主机**。技术 ID 不在首屏显示。

### 2.3 底部
- Compact 布局使用底部 Navigation Bar，仅显示已经实现的目的地。
- 点击 Agent 进入对话后隐藏主导航，返回后保留过滤条件与滚动位置。
- 大屏设计预留 Navigation Rail，但本版不要求实现。

## 4. 布局参数（候选值，评审后冻结）

| 部件 | 尺寸 / 规则 | 注意 |
|---|---|---|
| Compact 内容区域 | 320–599dp 窗口宽度 | 依据窗口宽度，不用物理屏幕分辨率 |
| 标准画板 | 393dp | 不包括系统栏、显示缩放和键盘 |
| 页面左右内边距 | 20dp（≤359dp 时 16dp） | 保证 320dp 可用 |
| 主标题 | 26sp / 34sp，SemiBold | 1.3/1.6 字体缩放需重排 |
| 分区标题 | 14sp / 20sp，SemiBold | 与任务标题区分 |
| 任务标题 | 16sp / 24sp，SemiBold | 最多 2 行，截断有完整阅读路径 |
| 条目摘要 | 14sp / 21sp | 只显示可靠来源 |
| 元信息 | 13sp / 19sp | 不使用 11sp 描述关键状态 |
| 高关注容器 | 16dp 内边距、16dp 圆角、1dp 边框 | 高度随内容增长 |
| 普通行 | 最小 64dp，可扩展 | 整行可点击，点击区域≥48dp |
| 行间分隔 | 1dp subtle line | 不对每行套大卡片 |
| 分区之间 | 24dp | 空组按规则隐藏或收起 |
| 主操作按钮 | ≥48×48dp | 图标本身可 20–24dp |
| 底部导航 | Material 3 原生尺寸 / Insets | 不自造硬编码系统栏高度 |

### 4.1 低密度与高密度
- **0 Agent**：清楚区分“主机在线但未发现 Agent”与“主机离线无法获取 Agent”；提供切换主机/重连/查看连接说明，不用空白页面填满装饰。
- **1–2 Agent**：按真实状态显示，页面可以保留自然留白；不为了填满屏幕而增加无数据的统计图。
- **3–8 Agent**：Blocked 1–2 个突出，其余按分区紧凑排列。
- **12+ Agent**：高关注卡片数量封顶，支持组内展开；保持 LazyColumn、稳定 Key，避免每一行持续动效。

## 5. 视觉规范与语义色

继承 Engineering Contract v0.1 的候选 Color Tokens（正式通过对比度检测后冻结）：

- Light：Canvas `#F7F8FA`、Surface `#FFFFFF`、Raised `#EFF2F6`、Border `#DFE5ED`、Text `#172033`、Secondary `#4F5D70`、Accent `#3556CE`。
- Dark：Canvas `#10151D`、Surface `#181F2A`、Raised `#222B39`、Border `#344052`、Text `#EEF2F8`、Secondary `#AEB9C8`、Accent `#9BB0FF`。
- **语义色单信号**：每个 Agent 条目最多一处强语义色（例如 Blocked 卡片左边框或状态标签），其余状态文字、箭头为中性；禁止“彩色点 + 彩色字 + 蓝色箭头”叠加。
- 状态必须有文字：Blocked「需要处理」、Working「运行中」、Done「已完成」、Idle「空闲」、Unknown「状态未知」。这些标签仅解释 Agent 状态，不等同于传输连接状态。
- 深色方案主要靠 1dp 边框、排版、背景层级建立秩序，不靠大面积阴影、模糊或不断发光。
- 正文色对比度应≥4.5:1，大字号≥3:1；实际组合逐个计算，不因选定 Token 就视作验证通过。

## 6. 交互与状态矩阵

| 场景 | 展示 | 可执行动作 | 禁止行为 |
|---|---|---|---|
| Online + fresh | 正常内容，连接低强调 | 打开对话、切换主机、同步 | 永久成功 Banner |
| Online + stale | 「内容更新中 / 显示缓存」 | 刷新、进入只读对话 | 把过期 Blocked 当实时批准 |
| Connecting | 保留已有缓存并显示连接中 | 切换主机、返回 | 全屏白屏阻挡已缓存内容 |
| Reconnecting | 非阻塞状态条 | 查看/重试（依状态） | 每次瞬断都弹 Dialog |
| Offline | 缓存有明确时间/过期标记 | 重连、只读查看缓存 | 显示“最新” |
| Auth / Host key mismatch | 明确安全状态 | 查看主机详情/安全操作 | 静默信任或重置密钥 |
| No host | 空态引导 | 添加主机 | 假造 Agent |
| Host online, no agent | 简洁空态 | 手动刷新、切换主机 | 当作“主机离线” |
| Blocked | 突出需注意 | 进入对话查看详情 | 无结构化 L1 审批时一键批准 |
| Working | 中性/低强调状态 | 进入对话 | 永久旋转/持续闪烁 |
| Done | 低强调已完成 | 进入对话 | 自动称为 Idle |
| Unknown agent | 清楚写“状态未知” | 进入详情诊断 | 染成成功绿 |
| Pending/Unknown write | 首屏可发现的谨慎提示 | 查看操作记录 | 自动重发或提示“发送失败” |

提示出现次序：安全异常 / Unknown 写操作优先于普通连接提示；多个通知不允许叠三条横幅压缩首屏。可采用单条优先横幅 + 可展开问题列表，确保所有事项仍能找到。

## 8. TalkBack 与可达性

- 整行可点击、单一朗读逻辑：`任务标题，Agent 名称，状态，项目名，主机名，数据是否过期，双击打开会话`；不重复朗读色点、Chevron。
- 操作入口至少 48×48dp，且与邻近区域不产生点击目标重叠。
- Section Header 提供标题语义；动态数量用合适的复数格式，不硬编码拼接。
- 主机选择器不应该只是难以辨识的小 Chevron；需要可见文案和明确点击区。
- 支持中英文、320/393dp、fontScale 1.0/1.3/1.6，标题栏高度必须适应文本而不裁剪。
- 系统减少动画设置时取消非必要状态过渡；所有实时状态可通过静态文案识别。

## 9. 动效（不阻断阅读）

| 事件 | 动画建议 | 降级策略 |
|---|---|---|
| 进入对话 | 淡入 + 小幅移动，220–280ms | 关闭转场 |
| 状态切换 | 颜色过渡，140–200ms | 直接切状态 |
| Blocked 新增 | 局部插入，无全屏抖动 | 立即出现 |
| 分区折叠 | 180–240ms，可中断 | 立即展开/收起 |
| 刷新 | 小型刷新反馈 | 不连续旋转 |
| 恢复连接 | 文字状态变化，不弹窗 | 直接替换文字 |

注意：动画仅改变表现，不作为完成/连接/成功的依据。

## 10. 视觉 QA 场景矩阵

**所有场景**都需要浅色与深色截图，至少有中文与英文各一版，另做字体放大专项。

1. 在线，0 Agent。
2. 在线，1 Agent（Working）。
3. 在线，2 Agent（1 Blocked + 1 Working）。
4. 在线，12 Agent（混合状态）。
5. 一台主机离线有缓存；切换另一台主机（当前没有跨主机聚合）。
6. 所选主机在线但快照暂时过期。
7. Pending/Unknown 写操作。
8. 主机指纹改变或需要重新认证（不得展示敏感私钥）。
9. 320dp，fontScale 1.3/1.6；测试标题、状态文字和底部导航的溢出。
10. 393dp，TalkBack 朗读与整行点击；返回后保留滚动/筛选位置。

**自动化验收**：已有 Compose UI 16/16 不回归；新增 Board Fixture + 状态测试。**真机验收**：读取真实 Herdr 状态、主机切换、断线缓存与重连、截图。已有 MIUI 的 instrumentation 限制应通过 AVD 自动化 + 真机人工检查弥补。

## 11. 评审时需要拍板的两项选择

**A. 主机选择器位置**
- A1（推荐）：位于页面标题下方，显示 `Dev-01 ▾` + 小的连接状态；顶部更干净。
- A2：与标题同行的 Top Bar 下拉；节省纵向高度，但更拥挤且在大字体下可能裁剪。

**B. 已完成分区默认行为**
- B1（推荐）：默认收起，仅显示数量；减少干扰，尤其有大量 Agent 时。
- B2：默认展开最近 1 条，其余折叠；用户更容易发现刚完成的任务。

在这两个决策明确前，不把文档标为 `Approved`，也不要让 Pi 根据自己的审美推断。
