## 2. 能满足的需求（已真机验证）

- **监督**：看板按状态分区（需要处理 / 正在跑 / 已完成 / 空闲），Attention 卡显示 eyebrow、meta 与 Agent 名；顶部单条 Banner 按「主机身份 > Unknown 写操作 > 认证失败 > 连接中 > 缓存过期」优先级提示；`● N 个 Agent` 汇总。
- **读对话**：Pi 与 Claude 两条链路都跑通。Claude 走「cwd → `~/.claude/projects/<slug>/` → mtime 最新 → 文件头 `sessionId` 三重校验」，任一不满足就诚实降级为终端尾部并显示原因。
- **消息渲染**：标题/列表/引用/围栏代码/行内码/加粗/链接、GFM 表格、工具卡（参数 + 输出，`结果已收到` / `尚未收到结果` / `未关联的工具结果`，>12 行进全屏页）、复制/更多/系统长按选择、搜索（250ms 防抖、n/N 跳转、命中高亮）。
- **发指令**：Composer 1–5 行、Enter 换行、48dp 发送、长 Prompt 全屏编辑；草稿独立 Room 库、跨进程恢复；发送「快照 + 单飞 + 结果分级清空」，写操作 Unknown 绝不自动重发，技术信息 Sheet 有「待确认写操作」入口。
- **连接**：SSH 连接复用 + SFTP 共享（进出会话不再反复重连）；断线重连、缓存过期标注、主机 Key 指纹校验（不自动信任）；主机编辑支持粘贴私钥或 SAF 选文件。

## 5. 已知问题（会遇到的）

1. **审批暂时用不上**：见 §3，需要真实触发源（pi 扩展或 Claude hook）才有请求进来。
2. 长 Markdown 消息滚动时，首行会被顶栏压住一点（需按 DESIGN-SYSTEM 行高复核）。
3. 会话缓存按回填窗口（1MB）加载；超出时列表顶部显示「只加载了最近的消息（更早的对话未下载）」。
4. 分支解析与条目映射仍是每次 O(n)（I-81），消息量大时滚动偶有掉帧。
5. 真机性能数据缺失：MIUI 拒绝 instrumentation，Macrobenchmark 只能在 AVD 跑（I-74/I-78），本版不宣称任何滚动/IME 性能指标。

## 6. 升级与回滚

- **升级**：同签名 `adb install -r`，Room 迁移 3→4→5→6 自动执行（只加列或清派生缓存，不清主机配置）。
- **回滚**：重新安装上一版 APK（签名一致才能覆盖）；如回滚到 debug 包需先卸载并重新配置主机。
- 签名文件 `~/.herdr/herdr-release.jks` 与 `android/keystore.properties` **不入库**（已加入 `.gitignore`），丢失后无法覆盖升级。

## 7. 0.1.1（真机首配时发现并修复）

**缺陷**：PEM 格式 RSA 私钥（`-----BEGIN RSA PRIVATE KEY-----`）导入后无法认证，界面反复显示「认证失败：Exhausted available authentication methods」。

**根因**：`SshConnector.loadKey` 无条件先用 `OpenSSHKeyV1KeyFile` 解析；对 PEM 私钥它**不报错但解析出错误的密钥**，于是 sshj 拿着不匹配的 key 去认证 → 服务器拒绝（桌面 JVM 探针复现：`luxiang_rsa` 用 PKCS8 解析可认证成功，用 OpenSSH v1 解析则失败）。

**修复**：按**文件内容**选择 provider —— 含 `BEGIN OPENSSH PRIVATE KEY` 用 `OpenSSHKeyV1KeyFile`，其余 PEM 用 `PKCS8KeyFile`（并保留 OpenSSH 兜底），返回全部成功者由 sshj 依次尝试。

**验证**：真机导入 `~/.ssh/luxiang_rsa`（PEM，4096 位）→ `HerdrConn: connected generation=1` / `ping ok version=0.9.5 protocol=22`；看板显示 `default` 会话 7 个 Agent（`docs/evidence/rel011-board.png`）。桌面 sshj 探针确认 `id_rsa`（OpenSSH 格式 RSA）在本机 SSH 服务上会被拒、`luxiang_rsa`（PEM）可用 —— 结论：**RSA 私钥请用 PEM 格式**，或改用 ed25519。
